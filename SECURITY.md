# Security Policy

FrostMail takes the security of its application, authentication infrastructure, and user data seriously. If you discover a security vulnerability, we appreciate your help in disclosing it to us responsibly.

---

## Supported Versions

Only the latest release running on the `main` branch is actively supported with security updates.

| Version      | Supported          |
| ------------ | ------------------ |
| 0.0.x (main) | :white_check_mark: |
| < 0.0.1      | :x:                |

---

## Reporting a Vulnerability

**Please do NOT report security vulnerabilities via public GitHub issues, discussions, or pull requests.**

Instead, report vulnerabilities privately by sending an email to:

📩 **`devfrost@protonmail.com`**

### What to include in your report:

- Type of vulnerability (e.g. Session hijacking, SSRF, DoS, injection, presigned URL leak)
- Step-by-step instructions or proof-of-concept (PoC) to reproduce the issue
- Affected endpoint, component, or file path
- Any relevant logs, payloads, or screenshots
- Potential impact and recommended remediation (if known)

### What to expect:

1. **Acknowledgment**: We will acknowledge receipt of your report within 48 hours.
2. **Assessment**: We will investigate and validate the vulnerability.
3. **Remediation**: We will work on a patch and notify you prior to publishing the fix.
4. **Credit**: We will gladly credit you in release notes (unless you prefer anonymity).

Thank you for helping keep FrostMail and its users secure!
